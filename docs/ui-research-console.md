# Research Assistant · UI 升级设计说明（feature/ui）

> 对象：Research Assistant Agent 科研工作台（React + Vite + Tailwind 4）
> 分支：`feature/ui`　　日期：2026-10-26
> 本文先立设计判断与交互规则，再据此做界面。界面实现与本文不一致时，以本文为准并回改实现。

---

## 1. 现状诊断（实测，非印象）

在 1440×900 首屏实测当前工作台：

| 观察项 | 现状 | 问题 |
|---|---|---|
| 左栏宽度 | 475px（33%），内部再分 header / 会话 / 消息 / 推荐指令 / 权限说明 / 输入框 六层 | 层级多、视觉噪音大，输入区被挤出主要视线 |
| 字号分布 | 10px ×16、10.5px ×16、11px ×13、11.5px ×9；正文 13.5px | 靠 10–11.5px 小字撑"精致"，实际阅读困难 |
| 装饰语法 | 圆角 5–10px 卡片 + 胶囊标签 + 大写字母眉标 + 每层描边 | 典型的"AI 生成 UI"语法：到处是徽章和卡片 |
| 主题 | 米色纸感底 #f5f2ea + 墨绿 #2c5a4d + 衬线标题 | "论文纸"隐喻停留在配色，信息结构仍是聊天机器人 |
| 文案 | "🎉 Agent 思考与执行完毕"、"哎呀，与后端失联了 📡"、✅❌ 表情 | 与科研工具的严肃语境冲突 |
| 状态表达 | 意图、outcome、模板规划、权限、ToT、Search Agent 六个徽标并排 | 重要状态被平铺，用户分不清轻重 |

结论：问题不在"颜色不够学术"，而在**信息架构仍是一个聊天应用**——对话、计划、执行三件事被塞进并排的两个卡片栏，状态靠徽标堆叠，操作靠重复按钮。升级要同时改骨架、语法和状态逻辑。

## 2. 北极星与调性

**北极星：像一台校准过的科研仪器——状态永远可读，动作永远有回执，装饰为零。**

五个刻度（依据：研究者长时间盯屏、任务以小时计、结果需要审计）：

| 刻度 | 取值 | 依据 |
|---|---|---|
| 能量 | 安静 | 低饱和、无渐变、无光晕；注意力留给数据和异常 |
| 完成度 | 精致 | 1px 公差、4px 网格、无阴影堆叠；仪器感来自对齐而非装饰 |
| 密度 | 密 | 科研工具默认高密度，但用留白和细线分组，不靠小字压缩 |
| 分量 | 中偏重 | 顶部深色仪器条与表头压住画面，主体轻 |
| 严肃度 | 庄重 | 直角 2px、无弹跳、无表情符号、文案陈述事实 |

模糊词翻译：
- "减少 AI 前端味" = 去掉胶囊徽章、渐变、圆角卡片套卡片、大写眉标、表情符号、无意义的"✨ Sparkles"装饰；一屏最多两个强调色，其余交给排版。
- "符合科研" = 表格化、可对齐的数字、版本/时间/哈希等标识用等宽字体、状态用灯位与字形而不是色块、报告区用衬线阅读字体。
- "优化交互与显示逻辑" = 一屏一个主动作；选择联动（图 ↔ 台账 ↔ 检查器）；权限模式常驻可见但解释收进浮层；运行时间与进度可见；错误带可执行下一步。

## 3. 三个方向（见 explore/a.html、b.html、c.html）

三个方向共用同一份示例内容（Apriori 复现，8 节点，4 完成 / 1 待审批 / 3 等待），骨架、字体、色彩、主视觉四项互不相同。

### 方向 A · 仪器台（Instrument Bench）
- **北极星**：一台校准过的实验仪器，运行轨迹本身就是界面。
- **生成引擎**：实验室仪器面板 + 图表记录仪。来源是产品真正在做的事——按节点推进的可审计执行。
- **骨架**：深色仪器顶栏（40px）+ 左栏会话/指令 + 右侧执行台（台头 / 元数据条 / 权限动作条 / 铺满的画布 / 运行标尺 / 节点索引条）。计划图是主角，不是卡片。
- **字体**：Segoe UI Variable Display/Text + Noto Sans SC；数值与编号一律 Cascadia Mono、tabular。
- **色彩**：冷灰 #EDF0F2 / 白面 #FFFFFF / 墨 #0F1418 / 普鲁士蓝 #1B4D6B（主操作）/ 琥珀 #94600B（待处理）/ 深绿 #2C6A4A（通过）/ 砖红 #9E2F26（失败）。
- **主视觉**：画布上的毫米方格 + 底部"运行标尺 + 节点索引条"（记录仪纸带）。
- **记忆点**：节点完成时索引条上的段落填色、标尺上"现在"的游标随执行推进。
- **结构性突破**：计划图下方常驻一条与图形同构的**运行索引条**，图形与时间轴一一对应，取代传统侧边节点列表。

### 方向 B · 论文校样（Journal Proof）
- **北极星**：一份正在被审阅的论文校样，执行记录是页边批注。
- **生成引擎**：学术期刊排版（masthead、图注、表注、页边校样符号）。
- **骨架**：刊头 + 对开双页（左页正文与批注，右页图 1 与表 1）+ 底部批注栏。
- **字体**：Noto Serif SC / Source Han Serif SC + Georgia；控件用无衬线小字号。
- **色彩**：纸白 #FBFAF7、墨 #17130F、校样红 #8C2C2C、细线 #D8D0C2。
- **主视觉**：带图注和比例刻度的"图 1 执行拓扑"。
- **记忆点**：页边逐条盖下的校样符号（✓ / ✗ / ○）与红色批注线。

### 方向 C · 观测站（Night Observatory）
- **北极星**：夜间观测台的控制台，一切读数都在暗适应下可读。
- **生成引擎**：天文台夜间红光/琥珀照明 + 示波器。
- **骨架**：全屏画布为底，会话、检查器、运行谱三块 HUD 浮在上面。
- **字体**：Segoe UI Variable + Cascadia Mono，大号等宽读数。
- **色彩**：夜空 #080C10、面板 #111820、文字 #D9E3EA、琥珀 #F2A03C、青 #6FD0DC。
- **主视觉**：带坐标刻度的星图式 DAG。
- **记忆点**：底部运行谱的实时波形与节点脉冲。

**推荐方向 A**：B 的"论文校样"容易停留在主题皮肤，且白纸衬线与现有米色纸感同源，改完仍像"换了字体的聊天页"；C 的暗色适合展示，但与产品核心的白色 PDF 阅读器长时间并置会产生眩光反差。A 保留高密度工具的可用性，同时把"执行中的仪器"这一产品真实属性做成界面骨架，最能同时解决"科研感"和"AI 前端味"两个问题。

## 4. 视觉系统（方向 A）

### 4.1 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | #EDF0F2 | 工作区底 |
| `--surface` | #FFFFFF | 面板、节点、检查器 |
| `--surface-2` | #F6F8F9 | 表头、输入底、次级面 |
| `--surface-3` | #E7EBEE | 选中底、标尺槽 |
| `--ink` | #0F1418 | 主文字 |
| `--ink-2` | #39434B | 正文 |
| `--ink-3` | #5D6975 | 辅助 |
| `--ink-4` | #85919C | 仅用于图标/禁用，不用于成句文字 |
| `--line` | #D6DDE2 | 分隔线 |
| `--line-strong` | #B8C2CA | 输入框、表头 |
| `--accent` | #1B4D6B | 主操作、选中、链接 |
| `--accent-soft` | #E3EDF3 | 选中底、提示底 |
| `--ok` / `--warn` / `--danger` | #2C6A4A / #94600B / #9E2F26 | 状态，只用于状态 |

规则：强调蓝不超过画面 8%；琥珀只用于"需要人处理"；不用渐变、光晕、彩色阴影。

### 4.2 字体与字号

- 界面：`"Segoe UI Variable Text", "Segoe UI", "Noto Sans SC", "Microsoft YaHei UI"`
- 标题：`"Segoe UI Variable Display"`，600，字距 `-0.015em`
- 等宽：`"Cascadia Mono", "Consolas", ui-monospace`
- 阅读正文（报告、论文译文）：`"Noto Serif SC", "Source Han Serif SC", Georgia`
- 字号：标题 15–18px；正文 13.5–14px；辅助 12–12.5px；等宽标签 11.5–12px；**任何正文不小于 12px，成句说明不小于 12.5px**。
- 所有编号、耗时、指标、版本号用 `font-variant-numeric: tabular-nums`。

### 4.3 空间与形状

- 4px 基准网格；面板内边距 12/16；区块间距 16/24。
- 圆角 2px（按钮、节点、输入框）；不出现胶囊、不使用 6px 以上圆角。
- 分隔只用 1px 细线，且每条线只承担一种分隔；不为每个层级加描边。
- 阴影只保留顶部仪器条下的 1px 硬边和浮层的一层软影；卡片不投影。

### 4.4 控件语法

- 按钮：直角 2px、高 30px（主）/28px（次）；主按钮实心蓝、文字 13px 600；次按钮 1px 描边、白底；悬停只变底色，不位移；按下 1px 下沉；禁用降为灰底灰字并保留光标说明。
- 输入：1px 描边、聚焦时描边转蓝并加 2px 外环；错误用砖红描边 + 文字说明。
- 选中：底色 #E7EBEE + 左侧 2px 蓝条 + 文字转深；不改变尺寸。
- 状态：统一用"字形 + 文字"（● 完成 / ◐ 进行 / ○ 等待 / ⚠ 待审批 / ✕ 失败），颜色是第二信号。
- 图标：统一 Lucide，16px、1.75 描边；纯图标按钮必须有 aria-label；不用 ✨ 类装饰图标。

### 4.5 动效（三处基本 + 一处记忆点）

1. **主操作反馈**：点击"运行计划"→按钮下沉 1px、右侧出现 2px 的进度细线；计划进入执行时顶部状态灯由琥珀转绿。
2. **状态切换的来路**：节点完成时，索引条对应段落先填色（从左向右 180ms），图形中的节点边框随之加深（延迟 60ms）；选中节点时，索引条与节点同时高亮，检查器从右侧滑入 220ms。
3. **首次进入**：执行台自上而下依次出现台头、元数据条、画布网格（透明度 0→1，每层间隔 50ms，总 300ms），只在首次挂载播放。
4. **记忆点**：运行标尺上的"现在"游标——一条 1px 竖线加一个三角标，随执行推进；待审批时停住并转为琥珀色，批准后继续前进。

手感：咔嗒（磁扣），150–220ms，cubic-bezier(.2,.8,.2,1)；不做弹跳；`prefers-reduced-motion` 下全部直达终态。

## 5. 交互逻辑与显示逻辑

### 5.1 一屏一个主动作

执行台台头右侧只出现一个主按钮，按状态切换：

| 计划状态 | 主按钮 | 次按钮 |
|---|---|---|
| 未开始 | 运行计划 | — |
| 待审批 | 审批并运行 | 取消 |
| 执行中 | 取消计划（危险色描边） | — |
| 有失败节点 | 重试失败节点 | — |
| 待运行操作授权 | 等待授权（禁用，指向动作条） | 取消计划 |

检查器内不再重复"启动任务"按钮；单节点重跑放在检查器的溢出菜单（`⋯`）中，避免与整图执行混淆。

### 5.2 三处联动

- 画布节点 ⇄ 运行索引条 ⇄ 检查器：点任一处的节点，另外两处同步选中；索引条支持 ↑/↓ 切换、Enter 打开检查器、Esc 关闭。
- 悬停索引条显示节点全名与耗时；悬停画布节点只加深边框，不弹卡片。
- 检查器宽度 380px，打开时画布 `fitView` 自动让出空间，关闭后恢复。

### 5.3 权限模式

- 常驻显示在执行台台头与输入区底部，用一个 28px 高的两段式开关（"确认模式 / 完全权限"）。
- 说明文字收进开关旁的 `?` 浮层（标题 + 三行说明），不再常驻一段 10.5px 灰字。
- 切到"完全权限"仍走原有确认对话框；确认框改为仪器风格（直角、表格式风险清单、勾选后按钮才可用）。

### 5.4 运行操作审批

- 有待审批动作时，动作条出现在台头与画布之间，不遮挡画布：左侧琥珀灯 + 标题，中间两列规格（操作 / 影响），右侧"允许一次 / 拒绝"。
- 动作条随计划状态消失；拒绝后计划转 blocked，动作条替换为失败说明与"查看缺失项"。
- 多个待审批动作折叠为"还有 N 项"，逐项展开。

### 5.5 消息流（实验室日志）

- 消息不再是气泡：每条记录由"序号 / 角色 / 时间 / 内容"四列组成，角色用中文（你、助手、系统、计划），时间等宽。
- 系统事件（计划生成、节点完成、失败）作为低对比日志行，保留可读性但不抢注意力；取消所有表情符号。
- 长报告在消息里只显示摘要 + "在检查器打开"，不整段塞进对话。
- 推荐指令改为"起始实验"列表（编号 + 一句研究动作），只在空会话出现；点击填入输入框，不直接发送。

### 5.6 显示逻辑

- 台头元数据条用"键: 值"表格呈现意图、步骤数、完成数、运行时长、权限；不再并排 6 个徽标。
- outcome/模板规划等低频信息移入台头右侧 `⋯` 菜单与检查器"计划信息"页。
- 缺失项（missing_requirements）以清单显示：名称 + 原因 + 建议动作，可复制。
- 检查器顶部固定"规格表"（负责智能体、状态、开始、耗时、退出码），下方才是日志/代码/报告/图表/证据/实验六个视图。
- 日志视图：行号 + 等宽 + 自动滚底开关；代码视图：行号 + 复制；报告视图：衬线正文、最大 68ch。

### 5.7 空态 / 错误态 / 加载态

- 空态：画布上显示 1px 网格 + 居中的"尚无运行"与三条起始实验，不画虚线卡片。
- 加载：骨架屏用真实的表格/图框轮廓，不用脉冲圆点。
- 错误：一句话说明发生了什么 + 一个可执行动作（重试 / 查看日志 / 复制错误码），不出现"哎呀"。

## 6. 实施记录

- **已落地**：方向 A「仪器台」已实现到 `research-assistant/frontend`（React 19 + Tailwind 4）。
- 顶部新增 44px 深色仪器条（品牌 / 计划标识 / 节点进度 / 运行状态灯 / 权限 / 账号）；左栏改为「当前会话 → 运行记录 → 指令」三段，消息按序号—角色—正文三列排布，不再是气泡。
- 执行台改为「台头 + 元数据条（步骤/完成/进行中/待处理/权限）+ 审批条 + 画布 + 节点索引条」；索引条与画布联动，支持 ←/→/Home/End 切换、双击打开检查器。
- 权限说明收进 `?` 浮层；完全权限确认框改为表格式风险清单（镜像/依赖/数据/算力），勾选后才可确认。
- 检查器新增四格规格表（智能体 / 状态 / 类型 / 节点编号），主操作降级为次级描边按钮，避免与整图执行抢主次。
- 全站圆角统一为 2px，取消卡片阴影堆叠，去掉全部表情符号；等宽字体承载编号、状态与数值。

**动效（三处基本 + 记忆点）**：主按钮按下 1px 下沉并即时反馈；检查器 220ms 从右侧滑入（只位移不淡入，避免首帧低对比）；节点索引选中时顶部 2px 蓝条即时出现、下方进度条从 0 填充；节点完成时画布顶部出现一条 33% 宽的运行脉冲。`prefers-reduced-motion` 下全部直达终态。

**评审**：本轮由主 Agent 用两轮自动化走查代替独立人工评审（当前会话的看图模型不可用，视觉评审子代理返回 CANNOT VIEW IMAGES）。验证方式为：Playwright 逐视口取真实截图、DOM 逐文本节点计算对比度与字号、检测溢出与裁切、对计划图做节点重叠检测，并跑通 11 条 E2E（含 6 条 axe 无障碍用例）与 6 条 Linux 视觉基线。
