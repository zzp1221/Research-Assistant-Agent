# 新增功能建议

> 本文基于 2026-10-26 的运行审计，给出“从研究原型走向研究平台”的功能建议。
> 选取原则：优先补“科研工作流刚需 + 现有数据/架构可复用 + 能形成复利”的能力；避免为了功能而功能。
> 每项包含：用户价值、核心能力、依赖、工作量/影响、验收标准。

## N-01 计划库 / 研究工作区（Plan Library）

**用户价值**

- 研究任务是长期的：用户需要看到“我跑过哪些计划、结果如何、哪次最好”，而不是只能靠 localStorage 或截图。
- 跨设备/换浏览器/清理缓存后仍能找回计划，是“研究助理”最基本的产品预期。

**核心能力**

- 服务端 plan/session 列表：按 owner、状态、类型、时间过滤；分页/游标；搜索标题/意图。
- 计划卡片：状态、outcome、节点数、耗时、成本、关键指标、缩略图。
- 项目（Project）分组：论文、数据集、计划、实验、报告归到同一研究项目。
- 操作：重命名、归档、删除、复制、导出、分享只读链接。
- 前端只存 plan id/摘要，不再把完整 PlanGraph 塞进 localStorage。

**依赖**

- Top10 #9（计划列表 API、游客身份、localStorage 瘦身）；
- R-08（删除/归档/导出）；
- R-04（分页/限流）。

**工作量与影响**

- L（约 2–3 周）；高影响，直接决定留存与跨设备体验。

**验收**

- 刷新/换浏览器/登录后可看到最近计划；
- 1,000 个计划列表首屏 < 1 秒；
- 删除/归档后列表、详情、导出都不可访问；
- 支持按项目过滤与搜索。

## N-02 可复现性导出包（Reproducibility Bundle）

**用户价值**

- 科研用户需要把“这次运行”交给合作者/审稿人/半年后的自己；当前只有散落的 artifact 和截图。
- 可复现包是“研究助理”区别于普通 Agent 的核心卖点。

**核心能力**

- 一键导出 zip：PlanGraph、事件、代码、指标、日志、EnvironmentManifest、Dockerfile/requirements lock、数据/模型 hash、随机种子、运行命令。
- 环境重建：image digest + pip freeze + 系统包 + 数据 hash；支持“按原环境重跑”。
- Artifact 内容寻址（SHA-256）与下载接口；导出包带校验清单。
- 导出格式：zip + Markdown 报告 + 可选 PDF。

**依赖**

- Top10 #7（内容寻址 artifact store）；
- R-05（token/cost 记录）；
- R-08（下载接口）。

**工作量与影响**

- M（约 2 周）；高影响，直接提升科研可信度与传播。

**验收**

- 导出的 zip 在另一台机器上按 README 可重建环境并重跑；
- 包内所有文件有 SHA-256，校验通过；
- 报告包含环境、种子、指标、失败/限制说明。

## N-03 成本与预算控制台（Cost & Budget Console）

**用户价值**

- 研究任务可能消耗大量 token/GPU/存储；用户需要知道“这次花了多少、还能花多少”。
- 团队/实验室需要预算控制，避免单个实验耗尽配额。

**核心能力**

- 每节点/每计划：prompt/completion tokens、美元、GPU 分钟、沙箱时长、下载字节。
- 计划级硬预算：tokens/USD/分钟；超预算暂停或拒绝。
- 模型路由：规划用便宜模型、代码/分析用强模型；provider fallback。
- 预算预警：80%/100% 通知；历史趋势。

**依赖**

- R-05（usage 记录与指标）；
- N-01（计划详情）；
- R-04（配额/限流）。

**工作量与影响**

- M（约 2 周）；高影响，是“预算受限 AutoResearch”的产品化闭环。

**验收**

- 计划详情显示总费用与各节点费用；
- 超预算计划自动暂停/拒绝，并给出原因；
- 模型路由可按 task type 配置。

## N-04 真实文献与网页检索

> 改进版设计见 [N-04/N-07 改进设计与实施方案](../design/n04-n07-literature-and-document-intelligence.md)：后端已有 arXiv/OpenAlex/Crossref/GitHub 检索与导入，重点补前端发现层、文献库、网页正文与引用图谱。

**用户价值**

- 没有真实检索的“Research Assistant”只是 LLM + 上传文件；用户需要文献综述、官方仓库、数据集、引用。
- 减少“模型编造论文/仓库/指标”的风险。

**核心能力**

- arXiv / Semantic Scholar / OpenAlex / Crossref / PubMed / GitHub Search，带 token、缓存、限流、重试。
- URL/DOI/arXiv ID → 自动下载 PDF、元数据、官方仓库候选。
- 引用图谱、论文库、去重（DOI/arXiv ID）、BibTeX 导出。
- 检索结果写入 ResearchContext，节点通过 InputBindings 消费；引用可点击。

**依赖**

- R-07；
- N-07（PDF 解析/OCR）；
- Top10 #3（API 身份/限流）。

**工作量与影响**

- M（约 2–3 周）；高影响，是“研究”能力的分水岭。

**验收**

- 输入 arXiv URL 可直接生成带元数据/PDF 的计划；
- 文献调研结果 100% 带可点击来源；
- 重复 DOI 不重复下载；
- 检索失败有明确 fallback 与提示。

## N-05 计划审阅与人在回路（Plan Review & HITL）

**用户价值**

- 当前只能“整图运行/取消/重试”；昂贵执行前无法修正计划。
- 研究过程需要人判断：换数据集、改超参、跳过某节点、从某步重跑。

**核心能力**

- DAG 编辑器：增删节点、改参数、跳过节点、从某节点开始运行。
- 暂停/恢复计划；修改后生成新 revision。
- 把后端 `ask_user_question` 工具接到前端：结构化提问、选项、等待用户回答后恢复。
- 审批收件箱：跨计划查看 pending runtime action，批量批准/拒绝。
- 计划 diff：revision 之间对比节点/参数/预算。

**依赖**

- Top10 #2（审批状态机）；
- N-01（计划库）；
- R-15（未接入能力）。

**工作量与影响**

- L（约 3–4 周）；高影响，是从“自动执行”到“可控研究”的关键。

**验收**

- 用户可在执行前编辑节点参数并保存 revision；
- 暂停后恢复不丢状态；
- ask_user_question 在 UI 中可回答并继续计划；
- 审批收件箱支持批量操作与审计。

## N-06 实验对比与指标看板

**用户价值**

- 研究是迭代：用户需要比较多次 run 的指标、失败原因、环境差异。
- AutoResearch/Benchmark 的 trial ledger 需要可视化，而不是 JSON。

**核心能力**

- 跨 run 指标趋势、A/B 对比、种子方差、置信区间、显著性检验。
- AutoResearch trial ledger 时间线、best candidate diff、失败原因聚类。
- Claim-Evidence 图与 PDF 页联动；证据强度/缺口提示。
- 导出对比报告（Markdown/PDF）。

**依赖**

- R-05（指标/成本）；
- N-02（导出）；
- N-01（计划库）。

**工作量与影响**

- M（约 2–3 周）；高影响，提升研究迭代效率。

**验收**

- 选择 2–5 个 run 可生成对比表/图；
- 指标差异有统计说明（均值/方差/样本数）；
- best candidate 可 diff 代码/参数。

## N-07 文档智能（OCR/版面/表格/公式）

> 改进版设计见 [N-04/N-07 改进设计与实施方案](../design/n04-n07-literature-and-document-intelligence.md)：Tesseract OCR 兜底已落地，重点补逐页混合 OCR、版面/表格/图注与质量报告。

**用户价值**

- 科研 PDF 常有扫描版、双栏、表格、公式、图注；仅 pdftotext 会丢失关键信息。
- 高质量解析是论文分析/复现的前提。

**核心能力**

- OCR（Tesseract/PaddleOCR）与语言检测；扫描版 PDF fallback。
- 版面分析（标题/作者/章节/双栏）、表格抽取、图注/公式抽取。
- 章节树与页码映射；引用 span 校验；术语表/翻译记忆。
- 解析质量报告（页数、字符数、失败页、置信度）。

**依赖**

- R-06；
- N-04（元数据校正）。

**工作量与影响**

- L（约 3–4 周）；高影响，直接提升论文分析质量。

**验收**

- 扫描版 PDF 可提取文本并完成分析；
- 表格/图注可被节点消费；
- 引用可定位到页码/章节/原文 span。

## N-08 数据/模型注册表

**用户价值**

- 研究需要真实数据集/模型；当前只能上传，缺少版本、license、hash。
- 复现需要知道“用的哪个版本、是否允许使用”。

**核心能力**

- HuggingFace/Kaggle/UCI 数据集导入；模型权重缓存与校验。
- license/版本/hash/大小/来源；数据集卡片；隐私/合规标记。
- 数据预览、统计、split 可视化；与 Benchmark/AutoResearch 集成。
- 下载缓存与去重；离线镜像。

**依赖**

- R-08（存储/配额）；
- N-04（检索）；
- Top10 #7（artifact store）。

**工作量与影响**

- M（约 2–3 周）；中高影响，支撑真实实验。

**验收**

- 可从 HuggingFace 导入数据集并生成 manifest；
- 模型/数据 hash 写入 EnvironmentManifest；
- license 不合规时阻止计划或提示。

## N-09 可观测性与运维

**用户价值**

- 研究任务长、调用多；用户/运维需要知道系统是否健康、哪个计划卡住、成本多少。
- 生产化需要 SLO/告警/审计。

**核心能力**

- Prometheus 指标 + Grafana 看板；OTel trace per plan/task。
- 计划看门狗：无心跳/无事件告警；自动重试或标记 needs_review。
- Sandbox reaper：TTL、孤儿容器、磁盘/内存用量。
- 结构化日志（plan_id/task_id/trace_id）；审计日志导出。
- 健康检查区分 liveness/readiness；provider 状态。

**依赖**

- R-05；
- Top10 #6（sandbox 生命周期）。

**工作量与影响**

- M（约 2 周）；高影响，降低运维成本。

**验收**

- Grafana 有 plan/task/LLM/sandbox 核心指标；
- 卡住计划 10 分钟内告警；
- 审计日志可按用户/计划/时间检索。

## N-10 通知与调度

**用户价值**

- 研究任务通常几十分钟到几小时；用户不应一直盯屏。
- 定时/周期实验（如每晚跑 benchmark）是常见需求。

**核心能力**

- 完成/失败/审批待办通知：邮件、webhook、IM（飞书/Slack）、桌面。
- 计划 watch list；通知偏好/静默时段。
- 定时任务（cron）、周期实验、失败重试策略。
- 与 N-01 计划库联动。

**依赖**

- R-09（可靠事件）；
- R-13/N-01。

**工作量与影响**

- S–M（约 1–2 周）；中影响，提升留存。

**验收**

- 计划完成/失败 1 分钟内收到通知；
- 可配置通知渠道与事件类型；
- cron 计划按预期触发，失败有重试/告警。

## N-11 CLI / SDK / OpenAPI

**用户价值**

- 研究用户常在 notebook/终端工作，而不是浏览器；需要脚本化提交、查询、下载、重跑。
- 团队集成/CI 需要稳定 API。

**核心能力**

- OpenAPI 规范 + 自动生成 TS/Python client。
- CLI：`ra plan submit`、`ra plan watch`、`ra artifact download`、`ra plan rerun`。
- Python SDK：notebook 中创建计划、订阅事件、取结果。
- API token/权限/限流与 Web 一致。

**依赖**

- R-04（API 健壮性）；
- N-01（计划库）；
- N-02（导出）。

**工作量与影响**

- M（约 2 周）；中高影响，扩大使用场景。

**验收**

- CLI 可完成“提交→等待→下载→重跑”闭环；
- SDK 在 notebook 中可用；
- OpenAPI 与实际 API 一致（CI 校验）。

## N-12 协作与分享

**用户价值**

- 实验室/团队需要共享计划、报告、证据；当前只有单机 localStorage。
- 审稿/合作需要只读链接与评论。

**核心能力**

- 计划/报告评论、@mention、任务指派。
- 只读分享链接（带过期/权限）；嵌入报告。
- 角色：owner/editor/viewer；团队/项目空间。
- 变更历史与审计。

**依赖**

- Top10 #3（真实身份）；
- N-01（计划库）；
- N-14（多租户）。

**工作量与影响**

- M（约 2–3 周）；中影响，团队场景必需。

**验收**

- 分享链接可只读查看计划/报告；
- 评论可定位到节点/claim；
- 角色权限测试通过。

## N-13 Agent/工具生态（MCP）

**用户价值**

- 固定 7 个 Agent 无法覆盖所有研究工具；用户需要接入自己的脚本、数据库、实验平台。
- 工具生态能让系统从“产品”变成“平台”。

**核心能力**

- MCP/HTTP 工具注册：schema、权限、超时、审计。
- 自定义 Agent：prompt、工具白名单、模型配置。
- Prompt 版本管理与评测；工具调用回放。
- 工具市场/模板（可选）。

**依赖**

- R-13（未接入能力）；
- N-05（HITL）；
- Top10 #3（权限）。

**工作量与影响**

- L（约 4+ 周）；中高影响，长期平台价值。

**验收**

- 注册一个自定义工具并在计划中调用；
- 工具权限/审计生效；
- prompt 版本可回滚/评测。

## N-14 安全与多租户

**用户价值**

- 从单机原型走向团队/生产，必须解决身份、隔离、配额、审计。
- 研究数据可能敏感（未发表论文、实验数据）。

**核心能力**

- OIDC/SAML、RBAC、团队/项目/角色；per-user token。
- Sandbox：gVisor/Kata、read-only root、非 root、seccomp、egress 代理。
- 上传扫描、PDF 解析隔离、密钥管理、审计日志。
- 配额/限流/成本预算；数据保留与删除策略。

**依赖**

- Top10 #3；
- R-15/R-01；
- N-01/N-03。

**工作量与影响**

- L（约 4–6 周）；高影响，生产化前置。

**验收**

- 多用户隔离/权限测试通过；
- 安全基线扫描通过；
- 审计日志完整可导出。

---

## N-15 研究模板 / Prompt 库

**用户价值**

- 新用户不知道如何写研究目标；模板能降低门槛。
- 团队需要复用“论文复现/基准评测/消融实验”的最佳实践。

**核心能力**

- 模板库：论文复现、框架评测、数据评测、AutoResearch、论文分析。
- 每个模板含：目标描述、默认 DAG、预算、附件要求、验收标准。
- 用户可保存自己的模板/分享；模板版本管理。
- 与 N-01/N-05 联动。

**依赖**

- N-01（计划库）；
- N-05（计划编辑）。

**工作量与影响**

- S（约 1 周）；中影响，提升新用户转化。

**验收**

- 选择模板可生成可执行计划；
- 模板可保存/分享/版本化；
- 模板执行成功率可统计。

## 路线图建议

| 阶段 | 目标 | 功能 |
|---|---|---|
| 0–1 月 | 让计划“找得到、带得走、花得明白” | N-01 计划库、N-02 导出包、N-03 成本账本（依赖 Top10 #7/#9、R-05） |
| 1–2 月 | 让研究“查得到、改得动” | N-04 文献检索、N-05 HITL/计划编辑、N-06 实验对比、N-07 文档智能 |
| 2–3 月 | 让平台“接得进、管得住” | N-08 数据/模型注册表、N-09 可观测性、N-10 通知/调度、N-11 CLI/SDK |
| 3–6 月 | 从个人工具到团队平台 | N-12 协作、N-13 工具生态、N-14 多租户、N-15 模板库 |

## 优先级判断

- **先做 N-01/N-02/N-03**：它们直接复用已有 PlanGraph/Artifact/事件数据，投入产出比最高，也是其他功能的基础。
- **N-04/N-07 是“研究能力”的分水岭**：没有真实检索和高质量 PDF 解析，系统仍停留在“LLM + 上传文件”。
