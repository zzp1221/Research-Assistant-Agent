# Architecture and flow diagrams

[简体中文](README.md) | English

This directory contains four editable draw.io diagrams with SVG previews and three separately maintained Archify HTML views. The root README displays the system, memory, and agent overviews directly; `runtime-flow` provides a separate detailed sequence.

## Files

| File | Purpose |
|---|---|
| `architecture.drawio` / `.svg` | Layered system architecture: clients and desktop shell, React workbench, Go backend, specialized agents, memory/tool layers, sandbox providers, persistence, and external dependencies |
| `runtime-flow.drawio` / `.svg` | Runtime sequence for one research task: plan creation, revision/review, scheduling, agent/tool/sandbox execution, artifacts, memory, SSE, and terminal state |
| `agent-execution-flow.drawio` / `.svg` | Agent architecture: task/context binding, built-in runners and domain loops, custom AgentProfile, model/tool/sandbox execution, acceptance, and state reporting |
| `memory-system.drawio` / `.svg` | Memory architecture: extraction and validation, reviewed cases, sessions and active windows, Memory/Paper Wiki, retrieval and shared budgets, materials, and model preflight |
| `system-architecture.html` | Archify interactive system architecture: desktop/server forms, control/execution planes, provider capability boundaries, external dependencies |
| `multi-agent-workflow.html` | Archify interactive multi-agent execution workflow: routing, approval, tools, sandbox, and evidence chain |
| `memory-system.html` | Archify interactive memory view: memory layers, retrieval, Wiki summaries and links, and persistence boundaries |
| `generate_diagrams.py` | Entry point generating all four `.drawio` / `.svg` pairs |
| `overview_diagrams.py` | Layout and rendering for the three overviews, sharing node, port, and waypoint geometry between draw.io and SVG |

## Regenerate

```bash
python3 docs/diagrams/generate_diagrams.py
```

To regenerate only the three README overviews:

```bash
python3 docs/diagrams/generate_diagrams.py architecture memory-system agent-execution-flow
```

The script overwrites the selected `.drawio` / `.svg` pairs. Overview layouts live in `overview_diagrams.py`; the detailed sequence lives in `runtime_flow()` in `generate_diagrams.py`. Overview nodes include repository-relative source references, and connectors use explicit orthogonal ports and waypoints. SVG labels use native text without `foreignObject`.

## Archify interactive diagrams

`system-architecture.html`, `multi-agent-workflow.html`, and `memory-system.html` are self-contained single files (inline SVG/styles/scripts) that open directly in a browser; they support light/dark themes, zoom/pan, and PNG/SVG export. All three are generated by Archify from repository source evidence, with `sources` references on key nodes.

The Python generator does not update these HTML views. They have not been synchronized with this revision's context, memory, and agent overview changes; the current README uses the `.drawio` / `.svg` versions.

Generation folders follow `.archify/<type>-<slug>-<timestamp>/` and keep `candidate.json`, the `.html`, and `.finalize-summary.json`. Regenerate and overwrite the same output after architecture changes:

```bash
node <archify>/bin/archify.mjs finalize architecture \
  .archify/architecture-<slug>/candidate.json \
  docs/diagrams/system-architecture.html --quality showcase --json
```

> Use the Archify package path installed on your machine; the candidate JSON's `meta.output` must point to `docs/diagrams/<name>.html`.

## Editing

1. Open `.drawio` files with diagrams.net or the VS Code Draw.io Integration extension; nodes and edges are editable.
2. For ongoing maintenance, change the layout scripts and regenerate the corresponding `.drawio` / `.svg` pair.
3. If editing directly in draw.io, export the matching SVG and copy the changes back into the layout data before the next generation.

## Visual conventions

- Blue: frontend / ordinary service nodes
- Green: specialized agents
- Orange: persistent state and artifacts
- Purple: memory, context, models, and research services
- Red: approval, validation, or isolation boundaries
- Overview solid arrows: main data/execution paths; dashed arrows: optional calls, projections, or supporting relationships
- In the detailed runtime view, yellow nodes mark decisions/boundaries and dashed edges mark events or result returns

## Maintenance requirements

- When architecture, providers, agents, or persistence boundaries change, update the affected draw.io / SVG pairs and README descriptions. Generate and validate the independent HTML views separately, documenting any unsynchronized scope.
- README architecture links point here; do not rename files.
- Generated files are large (Archify HTML is roughly 0.8 MB); before committing, confirm there are no local absolute paths or secrets.
