# Architecture and flow diagrams

[简体中文](README.md) | English

This directory contains three editable draw.io diagrams with SVG previews, plus two interactive Archify HTML diagrams. The draw.io diagrams are generated from layout data in `generate_diagrams.py`, so code reviews can update them in one place. The Archify diagrams are generated from repository source evidence.

## Files

| File | Purpose |
|---|---|
| `architecture.drawio` / `.svg` | Layered system architecture: clients and desktop shell, React workbench, Go backend, specialized agents, memory/tool layers, sandbox providers, persistence, and external dependencies |
| `runtime-flow.drawio` / `.svg` | Runtime sequence for one research task: plan creation, revision/review, scheduling, agent/tool/sandbox execution, artifacts, memory, SSE, and terminal state |
| `agent-execution-flow.drawio` / `.svg` | Agent execution details: task routing, AgentProfile, memory injection, tool calls, sandbox execution, artifact validation, and Claim Evidence / AutoResearch sub-loops |
| `system-architecture.html` | Archify interactive system architecture: desktop/server forms, control/execution planes, provider capability boundaries, external dependencies |
| `multi-agent-workflow.html` | Archify interactive multi-agent execution workflow: routing, approval, tools, sandbox, and evidence chain |
| `generate_diagrams.py` | Generates all three `.drawio` and `.svg` files from one set of layout data |

## Regenerate

```bash
python3 docs/diagrams/generate_diagrams.py
```

The script overwrites the same-named `.drawio` and `.svg` files. When changing layout, edit only the `architecture()`, `runtime_flow()`, and `agent_flow()` data in the script; never hand-edit generated files.

## Archify interactive diagrams

`system-architecture.html` and `multi-agent-workflow.html` are self-contained single files (inline SVG/styles/scripts) that open directly in a browser; they support light/dark themes, zoom/pan, and PNG/SVG export. Both are generated by Archify from repository source evidence, with `sources` references on key nodes.

Generation folders follow `.archify/<type>-<slug>-<timestamp>/` and keep `candidate.json`, the `.html`, and `.finalize-summary.json`. Regenerate and overwrite the same output after architecture changes:

```bash
node <archify>/bin/archify.mjs finalize architecture \
  .archify/architecture-<slug>/candidate.json \
  docs/diagrams/system-architecture.html --quality showcase --json
```

> Use the Archify package path installed on your machine; the candidate JSON's `meta.output` must point to `docs/diagrams/<name>.html`.

## Editing

1. Open the `.drawio` file with diagrams.net or the VS Code Draw.io Integration extension.
2. Edit nodes/edges and save.
3. Export SVG over the same `.svg`, or edit `generate_diagrams.py` and rerun it.

## Visual conventions

- Blue: frontend / ordinary service nodes
- Green: specialized agents
- Orange cylinders: persistent state
- Purple: external dependencies (LLM, Research Optimizer, literature sources)
- Yellow diamonds/notes: decisions, boundaries, cautions
- Dashed arrows: asynchronous returns, events, or result streams

## Maintenance requirements

- When architecture, providers, agents, or persistence boundaries change, update all three draw.io diagrams and both Archify diagrams.
- README architecture links point here; do not rename files.
- Generated files are large (Archify HTML is roughly 0.8 MB); before committing, confirm there are no local absolute paths or secrets.
