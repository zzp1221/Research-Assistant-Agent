本次依据 [设计基线](2026-11-06-model-aware-context-compaction.md) 实施，以下以代码和实际验证为准。原设计的服务商能力、跨模型密文兼容性与科研质量假设不作为已验证事实。

## 已落地

- `modelprofile.ContextPolicy` 保存协议、窗口来源、压缩模式、触发比例、摘要目标和四项独立能力声明。旧正数容量标为 `existing_config`；未配置容量标为 `unknown`，不再暗设 128k。创建和更新都校验模式与能力组合。
- `modelresolver.WithResolvedCall` 固定当次模型 revision。聊天、调度器、Planner、修复会话及自定义 AgentProfile 的文本生成进入共享运行时；预算、压缩、生成及价格归属使用同一配置。计划创建快照继续作为历史记录，调度预算不再使用旧快照。
- 输入预算为 `W - O - ceil(0.05W)`，触发线为输入预算乘配置比例。配置错误直接失败，不强行保留 1024 tokens。普通聊天取消 16000/24000/20 的模型容量限制；HTTP 4 MiB 限制独立保留。
- 独立 Responses 客户端支持 create、compact、显式启用的 input-token 计数，以及通过完整 `response.completed` envelope 提交 SSE 结果。原生 items 用 `json.RawMessage` 保存未知字段。独立模式保留 compact 返回的全部 items；仅 server 模式允许删除最新 compaction item 之前的前缀。
- 文本摘要仅用于显式选择 `chat_completions + text_summary` 的配置。一次摘要请求，无修复请求；校验完整 JSON 契约、来源 ID 和长度。首条用户请求、最新补丁/反馈与当前输入保留原文，摘要作为派生用户材料注入，不成为系统指令或长期事实。
- 修复会话不再根据 `MaxTurns` 删除中间尝试。Snapshot 包含可恢复的原始可见消息和活动窗口引用/版本；原生窗口从独立存储恢复，不由可见文本伪造。
- 聊天输入在模型预检/生成前保存。用户可见回答与模型原始文本分别保存，证据过滤不破坏下一轮原生窗口的前缀匹配。历史检索与规则摘要保留兼容接口，新的生成路径不再依赖规则摘要裁剪历史。专业任务每轮从业务模型追加当前目标、冻结契约和网络批准状态，不依赖密文是否保留这些约束。
- 同一分支按逻辑调用串行，原始输入 hash 去重，文件锁阻止其他 writer 重复提交；generation 以 CAS 校验并原子落盘。压缩先提交，后续业务生成失败不会回滚已完成压缩；重复同一输入可复用结果。不同 owner/project/session/task/repair branch 使用独立键。
- 原生状态以私有权限保存于 `CONTEXT_STORE_DIR`，默认在模型配置目录的 `context-windows` 下。每次提交保留不可变 generation，来源输入单独归档。审计和 API 诊断仅包含模型、版本、计数观测和压缩元数据，不包含密文或完整上下文。
- 压缩 HTTP 尝试单独计入 `context_compaction`，计入同一任务总用量。原生压缩价格未知时保持 `cost_source=unknown` 和空费用观测，不套用普通生成费率。server 返回压缩项时记录事件，额外客户端请求数为零，耗时为该生成请求的总耗时；无法拆分计价的合并 usage 也标为费用未知。计划/owner 设置有限费用时，不允许未知价格的原生压缩；server 请求省略自动压缩参数并记录 `budget_blocked`，原输入可容纳时继续业务生成。文本摘要预检同时计入摘要和业务生成的预计消耗。
- 模型设置提供容量、来源、协议、输出预算、模式、比例和能力状态；对话显示计数来源、窗口版本和最近压缩的请求数/耗时/费用状态。未知计数不显示虚构百分比，失败时恢复输入框内容。

## 启用与迁移

环境默认模型需要显式设置 `MODEL_CONTEXT_WINDOW_TOKENS`；兼容读取已有 `PROMPT_CONTEXT_WINDOW`。Docker Compose 从 `research-assistant/backend.env` 读取这些预算及 `CONTEXT_STORE_DIR`，配置示例见 `backend.env.example`。已保存的环境默认模型会迁移未知容量并刷新环境来源的容量；手动配置的正数容量保留。容量、模型、endpoint 或凭据变化会更新 revision 并重封装凭据。请求输出预算沿用 `PROMPT_MAX_OUTPUT_TOKENS`，缺省请求预算为 8192；这不是对服务商输出上限的声明。保存的模型配置可单独设置输出额度。

新旧模型默认保持 `chat_completions + off`，避免未经验证的接口自动启用。使用原生模式需在模型设置明确确认 Responses 及相应压缩能力；`unknown` 不启用。窗口缩小会重新检查预算；协议、模型、endpoint、凭据或模式变化时，从保留的可见原件重建，密文不会直接转发到新边界。

含密文或多模态 items 的精确计数仅在管理员确认部署支持 `/responses/input_tokens` 后调用，计数 HTTP 请求额外计入延迟/请求开销。未知时返回 `context_size_unknown`，已经成功压缩的 generation 仍保留。输入本身超限或旧窗口已超限时，返回可恢复错误，不发送无效 compact，也不分段发起隐式多次压缩。

## 与设计的实际交付边界

当前 Eino Agent 主要使用文本生成，工具由既有 ToolInvoker/独立任务执行。共享文本适配器拒绝结构化工具消息和未适配多模态消息，避免丢字段或重放工具副作用；原有视觉校验/视觉探测仍使用独立图像客户端，尚不宣称其图像 token 已获得统一精确计数。Responses 不创建额外工具权限。

2026-11-08 补充：上述限制仍适用于 Eino 文本适配器；新增 Profile `tool_loop` 使用专门的原生工具协议路径，能保存工具请求/结果及 Responses continuation，并接入同一上下文预算与 ToolInvoker。它不是将结构化消息强转成 Eino 文本，也不解除独立视觉路径的边界。

首版使用 stateless input-array 与 `store=false`，不提供 `previous_response_id` 或服务商自动能力发现。服务商模型支持、原生计数接口与压缩费率仍须按实际部署核验。首轮实施时官方文档入口返回 403，另一入口超时；后续真实模型测试时已可读取官方 Compaction 页面，结果见[真实模型测试记录](../test/2026-11-07-real-context-compression.md)。原生/摘要压缩的科研长任务质量和真实成本对照仍需更大样本评测，当前不扩大默认启用范围。

存储使用单个后端 writer 的本地文件语义，文件锁可阻止并发 writer；不作为多主分布式存储保证。活动窗口目录应按敏感会话数据管理备份和保留，原始 ChatStore 的删除不自动清理独立审计 generations。

## 验证

首轮自动化回归在 Docker 内运行，不调用付费模型。覆盖 32k/128k/200k 和非法预算、revision 固定及并发凭据一致性、环境容量迁移/刷新、计划用户路由、独立/服务端窗口规则、SSE 断流、压缩成功后生成失败及重启、并发去重、CAS、分支隔离、未知密文计数、过大输入、模型切换、摘要来源与失败回退、两种原生模式的费用预算限制、服务端合并用量及流式费用标记、聊天超过 20 条历史和长修复会话恢复。

已通过后端 `go test ./...`、关键上下文路径 `go test -race`、`go vet ./...`，以及前端类型检查、40 个组件测试文件中的 160 项测试、21 项单元测试、lint、生产构建和 bundle 预算检查。全部在 Docker 内执行。

测试使用挂载当前源码的临时容器，现有运行服务未重建为本次代码。临时测试容器及其中的日志/二进制在收尾清理；保留原有服务、数据和依赖缓存。

用户追加要求后，在实际后端容器运行了默认关闭的 `TestLiveContext*` 集成测试：真实文本摘要压缩及摘要后生成通过；当前网关的原生 compact 不可用，计数端点不存在，server 模式未观察到压缩项。测试未更改正式模型路由或能力配置。具体模型名称、请求结果和用量见真实模型测试记录。
